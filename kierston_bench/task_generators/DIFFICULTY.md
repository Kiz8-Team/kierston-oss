# Task-family difficulty audit

Reviewed 2026-09-07 against all 23 active Technical Task (TT) generators — the Real-Time Investigation (RTI) and Deception Task (DT) families are not yet graded — the KDI catalog, its identifier/subject resolvers, and the shared agent tools. These are code-based estimates, not measured solve rates or guarantees of answerability. They describe the currently exposed interface, including shortcuts, rather than the investigative story in generator comments.

A lookup is one `kdi query` invocation. Catalog discovery, retries, local analysis and internal SQL/resolver calls are excluded. Ranges assume a competent agent, populated records, and a modest candidate set; branching, missing identities and result limits can increase them substantially. Event searches commonly return a whole day: the agent must filter times locally. The catalog has no platform thread-history search, affiliation register, or trip/passenger manifest. Agents also have `km_address_lookup` and `km_search_places` outside KDI; those provide mapped address/POI coordinates and reverse lookup. Map calls are additional to the KDI counts below. This corrects the initial audit, which overlooked those tools.

Grades: **1 direct retrieval**, **2 short record join**, **3 focused evidence synthesis**, **4 branching investigation**, **5 broad reconstruction**. A missing evidence path is marked **gap**, not assigned a fictitious finite solve cost. Tactics are distinct operations such as identifier resolution, candidate discovery, temporal reconstruction, spatial matching and hypothesis comparison; issuing many queries of the same type does not create additional tactics.

## Evidence behind the grades

- [The TT generators](src/generators/technical/) define starting clues, selection rules and private targets. The [group index](src/generators/technical/index.ts) defines the 23 active families; [`groups.ts`](src/groups.ts) places them beside the RTI and DT groups.
- [Shared agent context](../eval_runner/src/context.ts) exposes `km_address_lookup` and `km_search_places`; mapping is available even though these are not KDI queries.
- [`ssa people`](../kdi/src/catalog.ts) exposes residence, parent names, occupation/SOC, employer and school. It supports address and identity search, but not reverse parent/employer search.
- [`subjectFor`](../kdi/src/resolve.ts) resolves subscriber name/DOB against SSA and can return SSN, address and mobile in the response header. Count this as one public lookup even though it executes multiple internal queries.
- [`platforms accounts`](../kdi/src/catalog.ts) returns owner names and DOB, including handle-only accounts. There is no platform conversation query.
- [`carriers network_events`, `cell_sites`, `alpr reads`, `alpr cameras`, `banks transactions`](../kdi/src/catalog.ts) support the main temporal/spatial investigations. None exposes simulation legs, meetings, ties or passengers directly.
- [`ssn_to_imsi`](../kdi/src/resolve.ts) uses account-holder SSN, not the subscriber identity; family plans can mix several people's movements unless the agent selects the right line.

## Interpretation

Use these grades for provisional task selection and budget planning, not score weighting. Keep a separate answerability assessment. A long search cannot recover a fact absent from the interface, and an apparently difficult family can collapse to one lookup through a subject header.

For calibration, record observed query count, distinct sources, candidate identities examined, investigative tactics, abstentions and answer score by family and variant. First split kinship by relation, account resolution by variant, location by moving/stationary, and occupancy by party size. Validate an observable solution path before calling a task solvable. This audit itself does not assign difficulty weights. The separate identity scoring policy changes answer-specificity credit and wrong-identity penalties.
